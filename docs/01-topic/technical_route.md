# 技术路线

## 1. 数据准备

1. 冻结具体课程或课程群。
2. 收集课程大纲、公开讲义、实验指导、FAQ 或合法授权资料。
3. 为每份资料登记标题、课程、章节、来源、日期、版本和许可证。
4. 清除重复文本、导航、无意义页眉页脚和格式噪声。
5. 按章节和语义边界切分文档，为每个文档块生成唯一 `chunk_id` 和 `chapter_id`。
6. 正式知识库控制在约 800–2000 个片段，并统计各章节片段数。
7. 知识库、测试集和索引均由本项目独立采集、处理、标注和存储。

## 2. 独立测试集

正式测试集不少于 150 条，核心分类为：术语定义、原理解释、流程步骤和易混辨析。每条问题至少标注问题类型、难度、标准答案和相关文档 ID。开发集可用于调参，正式测试集冻结后只用于最终评价。建议四类问题数量尽量均衡，若不均衡必须同时报告宏平均和各类别结果。

## 3. 检索方法

### BM25

对相同文档块建立倒排索引，记录分词器、停用词策略、`k1`、`b` 和 `top_k`。

### Dense Retrieval

使用固定 embedding 模型编码文档块和查询，使用余弦相似度排序，记录模型名称、版本、向量维度、归一化方式、运行设备和索引类型。

### Hybrid Retrieval

先对每个查询下的 BM25 与 Dense 分数分别归一化，再融合：

```text
hybrid_score = alpha * normalized_bm25
             + (1 - alpha) * normalized_dense
```

正式权重曲线测试 `alpha ∈ {0.0, 0.1, ..., 1.0}`，先使用开发集确定较优区间，再在冻结测试集上报告结果。不同量纲的原始分数不得直接相加，默认采用按查询 Min-Max 归一化，并对常数分数情况作明确处理。

### RRF

将两个排名按倒数排名融合：

```text
rrf_score(d) = 1 / (k + rank_bm25(d))
             + 1 / (k + rank_dense(d))
```

RRF 不依赖原始分数尺度。若作为第二种融合方式，应研究 `k` 参数并与加权融合比较。

## 4. RAG 问答

```text
问题 → 检索 Top-k → 可选 rerank → 构造上下文 → 生成答案 → 返回引用
```

BM25-RAG、Dense-RAG 和 Hybrid-RAG 使用相同生成模型、Prompt、测试问题和 Top-k，以保证比较公平。

## 5. 评估指标

- 检索：Recall@K、Hit Rate@K、MRR、平均延迟、P95 延迟；
- 问答：准确性、完整性、faithfulness、引用正确性、拒答正确率；
- 工程：索引构建时间、索引大小、内存占用和可复现性。

## 6. 实施顺序

```text
冻结统一评测协议
→ 课程范围冻结
→ 800–2000 片段知识库与开发集
→ BM25 Baseline
→ Dense Baseline
→ 加权融合与 RRF
→ 基础 RAG
→ alpha / RRF-k / Top-k
→ 消融实验
→ 四类问题统计与失败案例
→ rerank / query rewrite / 动态融合
```
